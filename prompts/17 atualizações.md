Contexto: Aplicação web já funcional (FastAPI, SQLite, interface em app/static) que coleta relatórios de repositórios do GitHub e mostra gráficos por repositório, incluindo o modo tendência; a coleta usa um cliente do GitHub e o token vem só da variável de ambiente GITHUB_TOKEN.
Objetivo: (1) Fazer todos os gráficos de tendência usarem o mesmo eixo de datas, com start e end em GET /api/trend calculados sobre todos os repositórios; (2) Permitir cadastrar repositórios do Azure DevOps por URL (por exemplo https://mondry-tech@dev.azure.com/mondry-tech/Note5/_git/Note5), detectando o provedor, guardando organização/projeto/repositório e coletando, atualizando por commit e exibindo como no GitHub, com mensagens de erro que digam se falta o token ou se ele foi recusado; (3) Guardar o token de cada provedor (GitHub e Azure DevOps) no banco de dados, cifrado com o DPAPI do Windows, com uma seção "Tokens de acesso" na janela da engrenagem para salvar, substituir e remover, sem nunca exibir nem devolver o valor, lido a cada requisição e com prioridade sobre as variáveis de ambiente; (4) Atualizar escopo, backlog, diagrama, README e testes.
Estilo: Python tipado e FastAPI em camadas, só com a biblioteca padrão (urllib, sqlite3, ctypes), sem novas dependências; o token nunca em texto puro no banco, nem em logs, respostas ou mensagens de erro; testes com clientes em memória e com o DPAPI real quando houver Windows; compatível com tema claro e escuro.
Resposta: Código completo dos arquivos novos e alterados em app/ e tests/, e os trechos atualizados de docs/01 escopo-mvp.md, docs/02 backlog.md, docs/03 diagrama-componentes.md e README.md.
